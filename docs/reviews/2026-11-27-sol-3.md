# Clipboard & Screenshot Archive — third-pass review

The Win32 clipboard-lock fix closes the previously reported privacy failure, and the restored `cactus.js` matches its pinned SHA-256. The remaining blockers include captures that outlive a settings change, restores that can suppress a genuine copy, and macOS folder imports that can archive unrelated files.

I reviewed the diff, its dependencies, and the test source. Per the brief, I did not build or run the app or tests.

## Important findings

1. **A capture can queue recognition after the user turns it off.** `src/main/images/image-capture.ts:179`, `src/main/images/screenshots.ts:284`, `src/main/images/screenshots.ts:418`. Capture snapshots `wanted` before waiting for the hash lock and file save. If the user disables recognition during that wait, `resume()` clears the queue before the new row exists. Capture can then insert a pending OCR row and enqueue it anyway. The result still passes the repository’s pending-state check and becomes searchable. For analysis, enqueue checks the current setting, so the same race can leave a row pending forever. Read the settings at record and dispatch time, and bind completion to the active request. Test both toggles with a gated file save and real queues.

2. **Pause can take effect while a capture is still eligible to commit.** `src/main/clipboard/capture-service.ts:235`, `src/main/clipboard/capture-service.ts:270`, `src/main/clipboard/screenshot-folder-import.ts:148`. Clipboard capture reads `captureEnabled` before the privacy retry, which can wait 310 ms. An ordinary copy can be persisted after the user pauses during that wait. Folder import checks pause before handing the path to the asynchronous image pipeline and has the same gap. Check a capture generation at the final record boundary so pause or shutdown invalidates in-flight work.

3. **Restore suppression can still discard a genuine copy, and mixed restores can finish out of order.** `src/main/images/screenshots.ts:184`, `src/main/images/screenshots.ts:410`, `src/main/images/screenshots.ts:441`, `src/main/clipboard/capture-service.ts:291`. An image capture can read pixels, wait on hashing or storage, then match a restore of the same pixels that started _after_ the capture. A pending marker has `sequence === null` and matches even on Windows. Without a version, a text restore can similarly consume an identical external copy when polling misses the restore itself. Separately, image restore reads the PNG before joining the write chain, so a later text restore can overtake it. Reserve the queue position when restore is requested and identify app writes with a per-write clipboard marker committed in the same write. Electron supports custom clipboard formats. [Electron ClipboardItem documentation](https://www.electronjs.org/docs/latest/api/clipboard-item)

4. **macOS imports from an unapproved source.** `src/main/app/clipboard-archive-app.ts:360`, `src/main/clipboard/screenshot-folder-import.ts:56`, `src/main/clipboard/screenshot-folder-import.ts:180`, `src/main/images/electron-images.ts:59`. With capture enabled, the app watches the system screenshot folder, usually Desktop. A fresh ordinary image with a matching name passes the filename and birth-time checks. The `stat` and read calls also follow symlinks, so the data can come from outside the watched directory. Require opt-in to a user-approved source, check screenshot provenance on macOS, and reject symlinks when opening candidates.

5. **Portable polling repeatedly copies and hashes the entire clipboard image.** `src/main/clipboard/electron-clipboard.ts:18`, `src/main/clipboard/watchers.ts:109`, `src/main/clipboard/watchers.ts:141`. Leaving a large image on the clipboard causes a full `arrayBuffer()` allocation and synchronous SHA-1 every 500 ms. This happens before the capture pipeline’s encoded-size limit. Use a native change counter where available and bound the fallback before copying or hashing the payload. Test that oversized blobs never reach `arrayBuffer()`.

6. **A stale `.verified` marker can still strand a damaged model at Ready.** `src/main/models/model-downloader.ts:111`, `src/main/models/model-downloader.ts:224`, `src/main/models/model-downloader.ts:240`, `src/main/images/screenshots.ts:472`. A same-size replacement that preserves `mtimeMs` passes the marker check. There is also a race between hashing the old bytes and stamping the path after a replacement. The worker rejects the damaged weights, then the UI recheck trusts the marker again and leaves recovery unavailable. Propagate the worker’s weights-integrity failure explicitly, invalidate the marker, and verify the identity of the file that supplied the hashed bytes before writing a marker.

7. **The packaged smoke test can pass without exercising the private-format decision.** `scripts/smoke-packaged.mjs:122`, `scripts/smoke-packaged.mjs:153`, `src/main/app/smoke.ts:76`. PowerShell reads back the private token’s text, but the app only checks its absence after a delay. A lost private notification or unreadable marker also passes. Verify the actual registered DWORD, wait for the app to acknowledge handling that clipboard change, and assert the `private-format` outcome. A public copy from the same writer with DWORD `1` gives a positive control. [Microsoft clipboard format documentation](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats)

## Minor findings

- **A cleared job can start a worker after shutdown has disposed it.** `src/main/workers/keyed-queue.ts:74`, `src/main/images/screenshot-feature.ts:245`. If `clear()` runs while `load()` is pending, `drain()` still calls `run()` when loading finishes. That can spawn a fresh worker after disposal. Check job ownership immediately after `await job.load()`. The test at `src/main/workers/keyed-queue.test.ts:315` currently expects the obsolete job to run.
- **The model’s cancellation boundary starts before rename.** `src/main/models/model-downloader.ts:207`. Cancellation during the awaited marker removal still publishes the file. A failed marker removal or rename can also leave `.download` behind because both are outside the cleanup block. Recheck cancellation immediately before rename and clean up failed publication. The deadline races network waits, while filesystem preparation can still delay completion past it.
- **OCR validates declared dimensions separately from the PNG.** `src/main/ocr/ocr-schema.ts:90`, `src/main/workers/worker-host.ts:61`. A request with small declared dimensions and a PNG header describing a much larger image reaches the decoder. Validate the IHDR dimensions against `width × scale` and `height × scale`, including a decoded-pixel limit. The worker’s output cap runs before sending, while main’s aggregate refinements run after deserialization and nested validation.

## Test quality and loader assessment

- The privacy regression explicitly holds the sequence constant while the simulated lock clears. The native-binding tests separately exercise failed `OpenClipboard` calls. Together they cover the original failure at the mocked boundaries. `src/main/clipboard/capture-service.test.ts:372`, `src/main/clipboard/win32/user32.test.ts:405`.
- The sweep regression uses the real capture service, store, and repository with a gate after the file-existence check. It exercises the original race. Add a gate that proves sweep reached the same hash and a second case where sweep acquires the lock first. `src/main/images/screenshots.test.ts:804`.
- The image-restore overlap test uses a fake serializer that lets the second write finish while the first is suspended. It exercises marker bookkeeping. The production ordering claim needs a mixed text/image test using the real `CaptureService` chain and a gated PNG read. `src/main/images/screenshots.test.ts:301`, `src/main/images/screenshots.test.ts:362`.
- The search E2E tests cover an open query and a multi-page refresh. Gate OCR until the capture-triggered search refresh has returned empty to prove the completion event itself brings the screenshot into the results. `tests/e2e/screenshot-search.spec.ts:17`, `tests/e2e/screenshot-search.spec.ts:38`.
- `evaluateCommonJs` closes the second-read race for the pinned script and supplies the CommonJS bindings this Cactus build uses. It executes trusted code with the utility process’s Node privileges. Its compatibility is specific to this bundle: normal `require()` also supplies module metadata, caching, cycle handling and loader semantics. `src/main/analysis/verified-script.ts:16`. [Node VM documentation](https://nodejs.org/api/vm.html) · [Node CommonJS documentation](https://nodejs.org/api/modules.html)
