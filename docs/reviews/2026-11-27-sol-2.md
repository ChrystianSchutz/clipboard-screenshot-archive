## Critical

1. **A Windows clipboard lock can defeat the privacy opt-out.** `src/main/clipboard/win32/user32.ts:148,165,213`, `src/main/clipboard/win32/win32-source-probe.ts:31`. If another app holds the clipboard open during the probe, all immediate attempts can fail and the DWORD read returns `null`. If the lock clears before Electron reads the text, the sequence can still match and a copy marked `CanIncludeInClipboardHistory=0` can be persisted. Distinguish an absent marker from an unreadable one. Retry against the same sequence with a short bounded delay and drop the capture if privacy remains unknown. Add a regression where the lock clears without a sequence change. [Microsoft Win32 clipboard documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard)

## Important

1. **The included Cactus script fails the runtime integrity check.** `src/main/analysis/mirage-model.ts:15`, `src/main/analysis/analysis-host-entry.ts:33`. The snapshot’s `cactus.js` hashes to `19ce92e4db6f9aff922938ed7626994e39537f2aca770e40b5c0d2ec186957cb`. The loader expects `707341e44776ab0eb8dfc8f6a579ed5ac41e2ffc6419a18012f61619a6dfc70c`. With these bytes packaged, users can successfully download the weights and still fail every analysis at startup. Restore the verified upstream artifact, then check the packaged bytes in CI and run one inference with the pinned weights. Bundle the JS inside the integrity-protected ASAR or load the verified bytes directly. The current checksum check and subsequent `require` open the loose script separately.

2. **The orphan sweep can delete pixels for a live clip.** `src/main/images/screenshots.ts:247`, `src/main/images/image-capture.ts:147`, `src/main/images/image-store.ts:33`. If a user recaptures the same image after deleting its row, capture can reuse the existing PNG while a sweep still considers its hash unreferenced. The sweep can then unlink the file after the new row is committed. Coordinate sweep and capture through the same per-hash lock, covering file reuse through database commit and the final reference check through unlink. Test a recapture during a sweep and clean up thumbnail-only leftovers from interrupted writes.

3. **Image-only copies can disappear in polling mode, and the macOS folder watcher is unwired.** `src/main/clipboard/watchers.ts:111`, `src/main/app/clipboard-archive-app.ts:336,399`, `src/main/images/node-screenshot-folder.ts:24`. The poller compares text hashes, so two successive images with empty text look identical. The macOS watcher has a factory and tests, but no application call site, so Desktop screenshots never reach `captureFile`. Use the native change counter where available and a bounded image-aware fingerprint elsewhere. Wire the macOS watcher into startup and shutdown, with pause and retention checks. Before enabling it, constrain imports to the user-approved source because its current filter accepts any visible PNG or JPEG in that folder.

4. **Text and image restores can suppress unrelated copies.** `src/main/clipboard/capture-service.ts:92,146`, `src/main/images/screenshots.ts:93,123,271`. A failed text write leaves its marker behind, so the next genuine copy of that text can be dropped. A pending image restore can also lose its marker when an older capture finishes, because the capture unconditionally clears the shared slot. Serialize app writes and bind suppression to the actual clipboard change using the native sequence or an app-specific clipboard marker. Cover failed writes, overlapping restores, and an external copy of identical content.

5. **Screenshot reads bypass the window-role policy.** `src/main/images/screenshot-protocol.ts:23,44`, `src/main/app/windows.ts:141`, `src/main/ipc/sender-policy.ts:22`. The image handler authorizes a method and URL in the shared session. A Compare renderer that issues an image request can receive screenshot pixels even though its IPC role denies screenshot access. Keep the positive safe-integer and variant checks. Register image serving only in the palette session, validate the trusted initiator where available, and exercise both the allowed and denied requests in a packaged test. [Electron protocol documentation](https://www.electronjs.org/docs/latest/api/protocol)

6. **OCR recovers the worker but loses the job, and disabled analysis can still commit.** `src/main/workers/worker-client.ts:53,86,121`, `src/main/images/screenshots.ts:183,200`, `src/main/storage/image-repository.ts:156,181,208`. A timeout or crash fails the current screenshot. The next task starts a fresh worker, but restart only reloads `pending` rows and the screenshot UI has no retry action. Disabling analysis resets the database state while jobs already in the queue can still finish and add searchable text. Give jobs a generation or request ID, validate it before committing, and stop queued work on disable or shutdown. Add a bounded retry for transient OCR failures and an explicit retry action for a failed screenshot.

7. **The work queues retain decoded images and image preparation runs on main.** `src/main/images/image-capture.ts:143,155`, `src/main/images/electron-images.ts:30,42`, `src/main/images/image-policy.ts:16`. Each new queued job closes over the decoded `NativeImage`. A burst of high-resolution captures can retain hundreds of megabytes while one OCR job runs. Native decode also precedes the dimension check, and hashing, resize, and PNG encoding run on main. Queue hashes and load images when jobs start. Bound encoded bytes and dimensions before decode where possible, and move expensive preparation behind a worker boundary. Keep the existing small thumbnails for list views.

8. **Search results stay stale after OCR or analysis finishes.** `src/main/storage/image-repository.ts:170,190`, `src/main/app/clipboard-archive-app.ts:132`, `src/renderer/src/features/history/useHistory.ts:111`. The repository updates extra text and FTS in one transaction, but completion only publishes `screenshot:updated`. If a search is open as a screenshot is indexed, the history list can remain empty until another change or a fresh query. Invalidate active history searches after the transaction. Test a pending screenshot entering an already-open query. Also test a refresh after multiple pages, since the current refresh replaces them with one budget-limited page.

9. **A corrupt local model can keep the UI stuck at Ready.** `src/main/models/model-downloader.ts:62`, `src/main/images/screenshots.ts:157,302`, `src/main/analysis/analysis-host-entry.ts:43`. The downloader reports readiness based on file existence. The worker correctly rejects a corrupted file, but the UI still sees Ready and the download path returns early. Validate the cached artifact before reporting readiness or propagate integrity failure into a recoverable model state. Offer replacement and test recovery from a truncated cache file.

## Minor

1. **The bundle handler’s containment is lexical, and the framing CSP is ignored.** `src/main/app/app-protocol.ts:32,43`, `src/renderer/index.html:7`. The path check rejects ordinary traversal and backslashes. In an unpackaged renderer tree, a symlink or junction can still resolve outside the bundle. The `frame-ancestors` directive in a `<meta>` tag also has no effect. Restrict serving to known build assets or verify resolved containment of unpackaged assets, allow only `GET` and `HEAD`, and send the production CSP as a response header. [CSP specification](https://www.w3.org/TR/CSP/#meta-element)

2. **The model transport has no overall deadline or HTTPS redirect policy.** `src/main/models/node-model-io.ts:11`, `src/main/models/model-downloader.ts:91,106`, `src/main/images/node-image-fs.ts:15`. The pinned size and checksum are checked before publication, and the same-directory rename prevents readers from seeing a partial final file. A stalled transfer can remain active until the user cancels, and redirects are followed without checking each destination’s scheme. Add an overall deadline, enforce HTTPS at every hop, and define cancellation at the rename boundary. Test cancellation during body reads and during file publication.

3. **Worker validation needs aggregate limits.** `src/main/ocr/ocr-host-entry.ts:31`, `src/main/analysis/analysis-host-entry.ts:46`, `src/main/ocr/ocr-schema.ts:16`, `src/main/workers/worker-protocol.ts:24`. Main validates response shapes, but field limits still admit millions of OCR word objects in one result. Validation runs after deserialization. The host also casts incoming messages directly to TypeScript types. Validate requests at worker entry, including encoded length and dimensions, and enforce total word, text, and output budgets before sending results. Use utility processes for crash isolation and account for their Node.js privileges in the threat model. [Electron utility process model](https://www.electronjs.org/docs/latest/tutorial/process-model#the-utility-process)

## What is good

- The renderer uses a sandboxed, context-isolated preload with narrow IPC channels. Sender authorization and argument validation run at the main-process boundary.
- The v2 backfill and v3 rebuild preserve clip IDs. Migration steps check foreign keys before commit and include the schema-version bump in the transaction. The fixtures cover data preservation and trigger sync. [SQLite table rebuild procedure](https://www.sqlite.org/lang_altertable.html#otheralter)
- OCR and analysis JSON are stored transactionally with their searchable text. The FTS triggers use a shared view and cover source changes, extra-text changes, and deletion.
- Packaging explicitly unpacks Koffi and Tesseract, ships OCR data and Cactus through `extraResources`, and verifies packaged startup and real OCR in Windows CI.
- History uses bounded previews with a deterministic keyset cursor. The image store uses pixel hashes for deduplication and small thumbnails for history rows.
