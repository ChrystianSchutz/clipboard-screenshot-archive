# Clipboard & Screenshot Archive — fourth-pass review

I reviewed the changed code, its dependencies, and the test source. This was a static review. I did not build the app or run any tests.

## Important findings

1. **A screenshot taken during pause can still be archived.** `src/main/images/screenshot-folder.ts:109`, `src/main/clipboard/screenshot-folder-import.ts:170`. The folder watcher waits 400 ms to confirm that the file has settled. If the user takes a screenshot while capture is paused and resumes before that wait ends, the import receives the new generation and commits. The same lifecycle gap exists at shutdown: an outstanding portable poll can call `onChange()` after `stop()` closes SQLite and receive the new generation (`src/main/clipboard/watchers.ts:122`, `src/main/app/clipboard-archive-app.ts:470`). Take the folder capture ticket when the watcher first sees the candidate, carry it through settling, and close the gate permanently at shutdown.

2. **Portable polling still loses genuine copies after a restore.** `src/main/clipboard/watchers.ts:141`, `src/main/clipboard/capture-service.ts:255`, `src/main/images/image-capture.ts:139`. If a poll sees a marked restore and the user then copies identical text or pixels from another app, the fingerprint stays the same and the watcher never reports the unmarked copy. There is also a gap after `readMarked()`: on a platform without a sequence counter, a restore can replace the image while the capture waits for the image queue. That capture can then ingest the restored pixels. Use a platform change counter where available. Include the marker in the fallback fingerprint and validate it around the actual pixel read.

3. **macOS provenance can be checked on a different file from the one archived.** `src/main/clipboard/screenshot-folder-import.ts:194`, `src/main/clipboard/regular-file.ts:25`. If a screenshot is replaced by another regular file after `xattr` succeeds and before capture opens the path, `readRegularFile()` takes a fresh identity and accepts the replacement. The descriptor check only binds the open to this second lookup. The `xattr` path also accepts a false-valued attribute because it checks exit status alone (`src/main/clipboard/screenshot-folder-import.ts:259`). Bind metadata and bytes to the same open descriptor and require an affirmative attribute value.

4. **Portable polling still materializes oversized images on each completed poll.** `src/main/clipboard/electron-clipboard.ts:88`. Electron 45.5.0 decodes the PNG, copies the encoded bytes to a Node `Buffer`, and constructs a `Blob` before `getType()` returns. Leaving a large image on the clipboard still incurs that work on each poll. The size check saves the additional `arrayBuffer()` copy and hash. Use change notifications or a counter so polling can detect changes without reading the payload. Any payload-based fallback needs a bound before full materialization. [Electron native image read](https://github.com/electron/electron/blob/v45.5.0/shell/browser/api/electron_api_clipboard_item.cc#L217-L249), [Electron Blob wrapper](https://github.com/electron/electron/blob/v45.5.0/lib/browser/api/clipboard-item.ts#L61-L68), [Node Blob copy semantics](https://nodejs.org/api/buffer.html#new-bufferblobsources-options)

5. **Automatic analysis can start after the user switches to On demand.** `src/main/images/screenshots.ts:250`, `src/main/images/image-capture.ts:248`. Put an automatic job behind a busy analysis worker and switch modes before it starts. `resume()` treats every pending hash as a `'user'` request, and the queued job can still start and save a result without an Analyze action. Track the request’s trigger through the queue and pending state so the mode change can withdraw automatic jobs while preserving explicit requests.

6. **Cancel and retry can hang past the download deadline.** `src/main/models/model-downloader.ts:249`, `src/main/models/model-downloader.ts:266`. If a temp-file write stalls and the user clicks Cancel, the cancellation handler waits for that same write through `cleanup`. The deadline cannot replace the existing cancellation reason. If the deadline fires first, the initial attempt returns, but the next attempt waits on the old cleanup outside its own abort race. Give each attempt its own temp path and clean it up once its I/O settles. Keep best-effort marker creation off the post-rename completion path as well (`src/main/models/model-downloader.ts:274`).

## Minor findings

- **A replaced model can still get a `ready` result for the current call.** `src/main/models/model-downloader.ts:145`. The replacement test puts corrupt bytes at the path before `status()` returns and explicitly expects `ready` on that call (`src/main/models/model-downloader.test.ts:444`). The next check rejects the replacement, and the worker can trigger recovery. Compare the path’s current identity with the hashed descriptor’s stamp before returning `ready`, and retry verification if they differ.
- **The folder read’s byte limit can be exceeded during the read.** `src/main/clipboard/regular-file.ts:38`. A writer that resumes appending after `fstat()` can make `readFile()` allocate beyond the limit before the decoder rejects the buffer. Read at most `maxBytes + 1` from the descriptor and reject overflow.
- **The packaged smoke test can fail after all three copies succeeded.** `scripts/smoke-packaged.mjs:231`, `src/main/app/smoke.ts:180`. The app can open the completion file after the script creates it but before the bytes are written. It then parses an empty file and reports a failure. Write to a temporary sibling and rename it into place.

## Race-test coverage

- Gated-save tests exercise real queues and storage for both recognition toggles. The queue-disposal test also holds input load and checks that `run()` never starts. The shutdown integration case disposes the queues directly and expects a row to commit, so it does not test the app’s capture gate or database close. `src/main/images/capture-settings-race.test.ts:200`, `src/main/images/capture-settings-race.test.ts:281`, `src/main/workers/keyed-queue.test.ts:443`
- The mixed-restore test uses the real write chain and a gated PNG read. The identical-copy tests call `handleChange()` directly or through the sandbox hook, bypassing the portable watcher where the copy is lost. Electron’s pinned source confirms that the standard data and custom marker share one native write. `src/main/images/screenshots.test.ts:383`, `src/main/clipboard/capture-service.test.ts:561`, `tests/e2e/capture-settings.spec.ts:74`. [Electron atomic clipboard write](https://github.com/electron/electron/blob/v45.5.0/shell/browser/api/electron_api_clipboard.cc#L303-L348)
- The model tests cover cancellation during marker removal, rename failure, and a first attempt timing out during a write. They release the blocked I/O before assessing cleanup and leave a retry against still-pending cleanup untested. The worker tests separately exercise error-code propagation and the application’s recovery response. `src/main/models/model-downloader.test.ts:653`, `src/main/models/model-downloader.test.ts:691`, `src/main/workers/worker-bodies.test.ts:101`, `src/main/images/capture-settings-race.test.ts:325`
- The gated OCR search test leaves 750 ms for the capture-triggered query to finish. A slow query can consume the OCR result after the gate opens and make the test pass without completion-triggered invalidation. Await the capture-triggered query’s empty response explicitly. `tests/e2e/screenshot-search.spec.ts:51`
