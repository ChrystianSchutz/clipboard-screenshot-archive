## Clipboard & Screenshot Archive — sixth-pass review

> Translated from Polish; the findings, verdict and file:line references are unchanged. Line numbers refer to the reviewed snapshot: the uncommitted multi-selection changes on top of `064e15a` (see `REVIEWS.md`).

Read-only review of the uncommitted multi-selection changes against `064e15a`. **0 critical, 6 important, 1 minor finding.**

### Important

1. **A batch copy can create a history entry by itself.** `src/renderer/src/features/history/useSelectionActions.ts:82`, `src/main/clipboard/capture-service.test.ts:359`. The joined text goes through the existing own-write marker mechanism. When the marker read returns `null`, or its token expires before the change is handled, the mechanism records the text as a new clip. For an ordinary Restore that only bumps the existing entry. Copying `A` and `B` can instead create a separate entry `A\nB`. The capture tests already reproduce both paths.
2. **A new clip can drop a row from the selection that still matches the filter.** `src/renderer/src/features/history/useHistory.ts:160`, `src/renderer/src/hooks/useListSelection.ts:45`. A refresh fetches as many rows as were loaded. When the user selects 60 rows and a new copy arrives, the last selected row falls outside the fetched range. The selection drops to 59, and a pending delete confirmation disappears. Reproduced on the History component.
3. **An open menu shows a different set than the one it acts on.** `src/renderer/src/features/history/ClipContextMenu.tsx:170`. The labels use a snapshot taken when the menu opened, while the actions use the current selection. I reproduced a refresh after which the menu still showed `Pin 60 clips` while 59 ids reached IPC. The menu should close or refresh when the set changes.
4. **History captures Enter on the confirmation buttons and loses focus after a Delete click.** `src/renderer/src/features/history/HistoryView.tsx:170`, `src/renderer/src/features/history/HistoryView.tsx:265`, `tests/e2e/multi-select.spec.ts:244`. Enter on a focused `Cancel` copies the selection instead of cancelling. After clicking `Delete` the next row is selected, but DOM focus lands on `body`, so the arrow keys stop working. I reproduced both. The current E2E checks the selection state after the click, but not DOM focus or activation with Enter.
5. **Deleting screenshots leaves their jobs in the OCR and analysis queues.** `src/main/app/history-mutations.ts:30`, `src/main/workers/keyed-queue.ts:59`, `src/main/app/history-mutations.test.ts:72`. The batch deletes the rows and schedules file cleanup, but does not withdraw the jobs through `KeyedQueue.withdraw`. After deleting a series of pending screenshots, the worker can still read and process their files, delaying recognition of the next images. The test that claims the work is removed from the queue checks the database, without a queue instance.
6. **The copy limit applies only after all content has been fetched and joined.** `src/renderer/src/features/history/useSelectionActions.ts:74`, `src/shared/types.ts:34`. With 500 selected clips of 1 million characters each, the code issues 500 IPC reads in parallel and tries to build a string of about 500 million characters before rejecting the operation. That can freeze the app or exhaust renderer memory. `charCount` is already in the list data, so the limit can be checked before any content is read.

### Minor

- **Ctrl+A in History needs focus on the list, which Tab cannot reach.** `src/renderer/src/features/history/HistoryView.tsx:244`, `src/renderer/src/features/history/HistoryView.tsx:344`. The list has `tabIndex={-1}`, and the arrow keys in the search box change the selection without moving DOM focus. A keyboard user of History has no path to the select-all shortcut.

### Verified

The new IPC channels require the palette's trusted main frame and validate 1 to 500 unique positive ids. SQLite runs each batch in one transaction. File cleanup relies on verified hashes and checks under a lock whether the image still has a database row. `src/main/ipc/sender-policy.ts:38`, `src/main/ipc/schemas.ts:20`, `src/main/storage/clip-repository.ts:312`, `src/main/images/screenshots.ts:369`
