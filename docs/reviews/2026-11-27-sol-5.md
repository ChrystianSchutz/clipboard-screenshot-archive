## Clipboard & Screenshot Archive — fifth-pass review

Static review of `CHANGES.diff`, its dependencies, and the test source. **0 critical, 4 important, 2 minor findings.**

### Important

1. **The portable watcher can archive a copy sampled during pause.** `src/main/clipboard/watchers.ts:180`, `src/main/clipboard/capture-service.ts:229`. A fallback poll can begin while capture is paused and finish an asynchronous clipboard read after resume. The callback then takes the new capture generation and can archive that copy. Take the generation when the poll begins and use it when delivering the result. Add a test that holds the poll across resume.
2. **Image backoff silently drops ordinary copies.** `src/main/clipboard/watchers.ts:216`, `src/main/clipboard/electron-clipboard.ts:88`. Once the fallback reaches 16 seconds, a user can copy a second screenshot, leave it on the clipboard for several seconds, and copy text before the next image probe. The screenshot never reaches history. The probe also still decodes and materializes oversized PNGs before the size check. Use platform clipboard change notifications where available and enforce the payload limit before materialization. [Electron 45.5.0 native image read](https://github.com/electron/electron/blob/v45.5.0/shell/browser/api/electron_api_clipboard_item.cc#L217-L249), [Electron Blob wrapper](https://github.com/electron/electron/blob/v45.5.0/lib/browser/api/clipboard-item.ts#L61-L68)
3. **macOS provenance still comes from a pathname.** `src/main/clipboard/screenshot-folder-import.ts:337`, `src/main/clipboard/regular-file.ts:89`. If the path temporarily names a different file during the metadata lookup and names the original again by the final check, both identity checks pass. The import can then archive the original descriptor’s bytes using the other file’s affirmative metadata. Read the attribute with `fgetxattr` on the open descriptor. Require descriptor-bound evidence for any provenance fallback. [Apple’s `fgetxattr` documentation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/getxattr.2#L104-L110)
4. **Migration 4 can discard a user’s pending Analyze request.** `src/main/storage/migrations.ts:65`, `src/main/images/screenshots.ts:272`. A v3 user in On demand mode can click Analyze, quit before it finishes, and upgrade. The migration labels the pending request `auto`, and startup withdraws it. Represent legacy requests explicitly and define how On demand handles them. Cover the upgrade with a v3 database fixture containing a pending request.

### Minor

1. **A replacement can still receive a stale Ready verdict.** `src/main/models/model-downloader.ts:159`. On a marker hit, replacing the weights while the marker read is pending returns `ready` for the old stat. On the hashing path, replacement can still happen while `writeMarker()` is awaited after the final stat. Recheck the identity after marker lookup and move marker writing off the verdict path. The current test only replaces the file during the hash. `src/main/models/model-downloader.test.ts:448`
2. **The OCR regression can accept the wrong empty query.** `tests/e2e/screenshot-search.spec.ts:75`, `src/renderer/src/features/history/HistoryView.tsx:37`. The list starts empty, so the zero-row assertion can finish before the debounced search is issued. The observer then accepts any empty reply, including an earlier query, and can release OCR while the intended search is still pending. Observe the query arguments, await the initial `ECONNRESET` reply before copying, and then await a distinct empty reply for that same search while OCR is held.
